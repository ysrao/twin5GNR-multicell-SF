What the optimiser may change, per §11 of the description: azimuth (search around current headings), electrical tilt (0–10°), transmit power (±2 dB), slice PRB shares, OLLA offset (±4 dB, action threshold 1 dB). The MCS cap is reported, never silently changed.

Step 3 — Select the function, hand the run to the twin

In the notebook: Runtime → Run all, and upload the package when asked. The runner traces the twin with Sionna RT, scores with Sionna SYS, evaluates the existing configuration from the counter dump, runs the optimisation, and applies the twin gate before emitting anything. It writes rapp_result.json — bring it back here.

Recommended changes

How the run works, honestly. The optimisation itself — the ray-traced twin, the SYS link curve and slice environment, the guarded search, the audit's histogram fit — is the prototypes' own code, and it runs in the notebook (Sionna RT + SYS), not in this page: a static page cannot ray-trace. This page prepares the run from the sites and the counter dump and presents what the twin verified. Nothing is emitted unless it passes the twin gate; a run that finds nothing worth changing says so and keeps the as-built configuration.
